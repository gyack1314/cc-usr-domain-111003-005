# HB-26 海湾观测站项目 处理依据与可重复检查方法

本文件说明本次投标响应归并的**判断依据、取证方式、产物位置与可重复操作方法**。所有主体、编号、文书均为本地合成数据，无真实投标账号；系统不自动签章、不投递、不宣称中标。

## 一、效力判断依据（仅以规程成文规则为准）

依据 `materials/policy.md`，在 `casework/params/policy.json` 机器转写后供程序使用：

| 规则 | 内容 |
|---|---|
| R1 | 仅 **HB招标中心** 来文有替代效力；供应商沟通、未盖章问答不产生替代效力 |
| R2 | 内部封版截止 **2026-11-10T12:00:00+08:00**；晚于该时点生效的变更不进入封版口径，独立留档 |
| R3 | 按**生效时点 + 明确替代关系**处理，不按上传/下载顺序、不按文件修改时间全序覆盖 |
| R4 | 撤回只作用于明确 target；被撤回件自撤回生效起不产生效力 |
| R5 | 一份来文只替代 `replaces` 明确指向的条款/附件，不覆盖未提及材料 |
| R6 | 附件独立编号，正文变更不自动替代附件；换附件须明确指向 |
| R7 | 同权限、无明确取代关系的冲突**保留并标阻止位置**，人工裁决，不臆造统一口径 |
| R8 | 禁止自动签章或投递；草稿恒为“待人工审批” |

系统当前日期不参与判断（见 `docs/operations.md`），所有时点比较均使用上述封版截止口径。

## 五、可重复检查方法（同一资料复跑不叠加文本）

门户（仅监听本机）：

```bash
python3 -I -c "import sys;sys.path.insert(0,'/workspace');from workbench.portal import main;main()" \
  --port 8765 --state /workspace/state/hb26
```

完整流水线（确定性、幂等；草稿写入需单独执行以便人工把关）：

```bash
# 1 浏览器取证（真实 Chromium，逐页浏览+下载，不读种子、不按下载顺序定性）
python3 -I casework/collect.py http://127.0.0.1:8765 evidence/hb26
# 2 裁决归并（复用 workbench.domain 的 patch/differences/referenced_targets）
python3 -I casework/determine.py evidence/hb26/evidence.json casework/params/policy.json state/hb26/analysis
# 3 生成修订后未签章副本（原子写、无时间戳，复跑字节一致）
python3 -I casework/revise.py materials state/hb26/analysis/determination.json evidence/hb26/evidence.json deliverables/HB-26
# 4 经浏览器表单保存封版意见草稿并回读指纹（不签章、不提交）
python3 -I casework/save_draft.py http://127.0.0.1:8765 evidence/hb26/evidence.json state/hb26/analysis/determination.json hb26-seal-opinion evidence/hb26/draft
# 5 进度账（同键同内容幂等，不同内容拒绝覆盖）
python3 -I casework/journalize.py evidence/hb26/evidence.json state/hb26/analysis/determination.json evidence/hb26/draft/draft-readback.json state/hb26/journal.sqlite3
# 或一键：python3 -I casework/run_pipeline.py
```

复查与变化识别：

```bash
# 无变化 → all_clear=true，退出码 0；有变化 → 退出码 3 并列出需重审副本
python3 -I casework/recheck.py evidence/hb26/evidence.json \
  state/hb26/analysis/determination.json deliverables/HB-26 \
  state/hb26/manifests/materials-manifest.json materials
# 原件/证据指纹核验
python3 -I -c "import sys;sys.path.insert(0,'/workspace');from workbench.tools import main;main()" verify materials state/hb26/manifests/materials-manifest.json
```

`recheck.py` 比对当前证据与裁决时记录的 `input_fingerprint`：来文指纹一变即按来源链映射指出受影响的具体副本字段（如 A6/A7→warranty 正文与附件、草稿冲突段），而不是全量重做；交付物被篡改则由 `deliverables-manifest.json` 报出。

测试：

```bash
python3 -m unittest discover -s tests          # 11 项，含新增 test_hb26_casework
python3 -m tests.browser_checks               # 临时状态，不影响日常草稿
python3 -m compileall -q workbench tests casework
```

## 六、安全边界

- 下载件每份独立目录存放；脚本位于 `casework/`，处理不可信资料统一 `python3 -I` 并以参数传路径，不从资料目录运行解释器，防止植入模块被导入。
- 不修改 `portal_data/` 种子与 `materials/` 原件；草稿写入门户 SQLite，状态恒为待人工审批。
- 负责人动作（裁决 warranty、签章、投递）不在本工作台能力内，留待人工。
